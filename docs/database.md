# Database design

MongoDB (Atlas replica set, MongoDB 8) accessed through Prisma 6 with the MongoDB connector. The schema is Prisma multi-file (`prisma/schema/*.prisma`): one collection per model, snake_case collection and field names via `@@map`/`@map`, string UUIDv7 primary keys stored in `_id`. There are no SQL migrations: the backend creates every index itself at start-up and via `npm run db:sync` (see "Indexes"); `prisma db push` is not used because it cannot express the partial indexes MongoDB needs here.

Founder decision 2026-11-07: PostgreSQL/Neon is retired; MongoDB is the only database. The HTTP API did not change.

Key modelling decisions (unchanged by the move to MongoDB):

- **`providers` is the shared core** (type, status, names, contact, rating); each type has a 1:1 detail collection keyed by the provider id. A doctor is a provider whose `doctor_profiles.user_id` is the doctor's login.
- **`doctor_affiliations`** is the doctor↔facility relationship with its own terms, confirmations and status; schedules and slots reference it so a suspension blocks the right slots only.
- **`service_transactions`** is the single money anchor for any billable thing (exactly one of four source ids, enforced in the service layer), so finance never branches on source type.
- **Money** is a 64-bit integer (`BigInt`, stored as BSON Long) of minor units plus an ISO currency code; rates are basis points. Floats are used only for coordinates and rating averages.
- **References, not embedding.** Documents hold foreign-key strings exactly like the relational design; Prisma emulates relations (`include`, `onDelete: Cascade | Restrict | SetNull`) client-side. This keeps the audit/history pattern and the API shapes identical. Embedding is reserved for data that is never queried on its own (JSON payloads, snapshots).
- **Soft history, not deletes**: role revocations, status histories, report versions, affiliation events and commission reversals are new documents.

## Primary keys and time

Ids are UUIDv7 strings generated by Prisma (`@default(uuid(7))`), time-ordered so `created_at` + `_id` form a stable pagination cursor. Dates are BSON dates (UTC instants, millisecond precision); opening hours and schedules store minutes-from-midnight interpreted in Asia/Kolkata by the application. Ids never change, so every relation declares `onUpdate: NoAction`.

## Transactions and concurrency

- Every multi-step write runs in an interactive `$transaction` (multi-document ACID; requires a replica set, which Atlas and the test harness provide).
- MongoDB has no row locks. Where PostgreSQL used `SELECT … FOR UPDATE`, the service now **writes to the anchor document first** (bumps `version` on `service_transactions` or `payment_webhook_events`). Two transactions touching the same document conflict; Prisma raises P2034 and `transactionWithRetry` (src/lib/prisma.ts) reruns the loser from the start. Capacity and stock use compare-and-set (`updateMany` on `version`): slot claims, inventory reservations, order status moves, settlement claims.
- Queue-style work (notification delivery, scheduled jobs) claims documents with atomic `findAndModify`; scheduled jobs additionally take a lease in `job_leases` so two worker processes never run the same job together.

## Indexes and why each exists

Declared in the Prisma schema and created from the generated manifest (`src/lib/mongo-index-manifest.ts`, 198 indexes):

| Index | Supports |
|---|---|
| `users(status, created_at DESC)`, `users(created_at DESC, id DESC)` | user list filters and keyset pagination |
| `users(full_name)`, `providers(display_name)`, `conditions(name)`, `services(name)`, `medicines(name)`, `conditions(synonyms)` | name/synonym search (prefix regex uses the index; contains falls back to a scan on these small catalogues) |
| `sessions(refresh_token_hash)` unique, `sessions(user_id, revoked_at)`, `sessions(family_id)` | refresh, logout-all, reuse detection |
| `providers(type, status, created_at DESC)`, `providers(status, created_at DESC)` | admin lists and verification queue |
| `provider_locations(district, pincode)`, `provider_service_areas(district, pincode, purpose)` | serviceability checks |
| `appointment_slots(doctor_provider_id, location_id, starts_at)` unique, `appointment_slots(starts_at)` | idempotent slot generation, public slot listing |
| `appointments(doctor_provider_id, created_at DESC)`, `(facility_provider_id, …)`, `(status, …)`, `(patient_profile_id, …)`, `(created_at DESC, id DESC)`, `(slot_id)` | every list the portals and admin use |
| `appointments(booked_by_user_id, idempotency_key)` unique | booking idempotency at the data layer |
| `service_transactions(provider_id, created_at DESC)`, `(status, …)` | finance lists |
| `provider_ledger_entries(dedupe_key)` unique | idempotent postings |
| `payment_webhook_events(gateway, event_id)` unique | duplicate delivery protection |
| `idempotency_records(user_id, scope, key)` unique | HTTP idempotency |
| `audit_events(entity_type, entity_id, occurred_at DESC)`, `(actor_user_id, …)`, `(action, …)`, `(occurred_at DESC, id DESC)` | audit search |

| `patient_profiles_one_self` | `relationship: 'SELF'` | one SELF profile per account |
| `appointments_patient_slot_live` | status in REQUESTED, CONFIRMED, CHECKED_IN | one live booking per patient per slot |
| `dispatch_assignments_one_accepted` | `status: 'ACCEPTED'` | one accepted crew per request |

| `payout_accounts_one_verified` | `status: 'VERIFIED'` | one verified payout account |

It also recreates, under the same names, the 20 unique indexes that involve an optional field (`users_phone_key`, `payments_idempotency_key_key`, the four `service_transactions_*_id_key` source links, …) as partial unique indexes covering only documents where the field is present: MongoDB would otherwise allow a single document without that field. The list is derived from the schema by `node scripts/list-optional-uniques.mjs` and guarded by a unit test.

`ensureIndexes()` is idempotent; an index whose definition changed is dropped and recreated. The API refuses to start if it fails, because the partial unique indexes are the last line of defence for the invariants above.

Deliberately **not** indexed: free-text fields other than names, low-cardinality booleans on small collections, every foreign key on tiny lookup collections. Each new index must name the query it serves.

## Rules PostgreSQL used to enforce, and where they live now

| Was | Now |
|---|---|
| CHECK constraints (coordinates, PIN codes, hour ranges, money ≥ 0, `booked_count ≤ capacity`, `reserved ≤ on_hand`, selling price ≤ MRP, policy bounds, one transaction source, maker ≠ checker) | Zod on every request body plus service-layer guards; covered by the integration tests |
| `appointment_slots_no_overlap_excl` (no overlapping slots for one doctor) | `generateSlots` loads the doctor's existing slots in the window and skips overlaps before insert; the unique index on (doctor, location, starts_at) catches races |
| `commission_policies_no_overlap_excl` (no two ACTIVE policies for one scope/period) | overlap check inside the activation transaction |
| Append-only triggers on ledger and audit tables | no update/delete code paths exist for those collections; settlement only sets `settlement_item_id` |
| Trigram similarity ranking | exact → prefix → contains tiers (case-insensitive regex) plus the synonyms arrays; Atlas Search can replace this without an API change |
| `citext` e-mail | e-mails are lower-cased before storage and lookup |

## Schema changes

- Edit the Prisma schema, run `npm run prisma:generate` (regenerates the client and the index manifest), then `npm run db:sync` (creates new indexes online; it never drops data). Every test run creates all indexes in an empty in-memory replica set, so an index that does not apply cleanly fails CI.
- Optional fields are always stored as explicit `null` (src/lib/prisma-null-defaults.ts) so SQL-style `where: { field: null }` filters work; documents written by other tools can be normalised with `npm run db:backfill-nulls`.
- Field renames need a backfill script (`scripts/`) run before the code that reads the new name is deployed: expand → backfill → contract, exactly as before.
- Rollback is forward-only; Atlas continuous backup gives point-in-time restore (see operations).

## Atlas specifics

- Use the `mongodb+srv://` string with `retryWrites=true&w=majority`. If a host cannot resolve SRV records, use the long form with the three replica members and `replicaSet=…&tls=true&authSource=admin`.
- Network access: allow-list the API hosts; the database user needs `readWrite` on the application database only.
- `DB_STATEMENT_TIMEOUT_MS` bounds one transaction; the driver pools connections per process.
- Atlas Search (Lucene) is the upgrade path for fuzzy catalogue search; nothing in the API depends on it today.

## Growth plan (evaluated by measurement)

`audit_events`, `appointment_slots`, `appointments`, `provider_ledger_entries` grow fastest. Options in order: keep (indexes are keyset-friendly) → TTL or archive of old audit documents after the retention period → Atlas Online Archive for cold audit and slot history → sharding by provider/time only if a single replica set measurably saturates.
